# Block 4: automatic visual atlas compaction

## Scope

The editor and CLI visual importers now share an automatic lossless atlas
compactor. This changes future generated visuals, not the hand-authored gameplay
scenes or the legacy schema/collision importer. No backend source or runtime stack
changes were needed. Existing generated map assets were not regenerated.

Only atlas regions referenced by cells are retained, including hidden layers.
The importer preserves cell positions, transformations, alternative IDs and
TileData, physics/custom layers and visual layer settings. There is no resizing.
Atlases have 2px borders, 4px separation, at most seven columns and dimensions
capped at 4096px. Large sources split with IDs that do not collide with other
original sources. Textures are external PortableCompressedTexture2D resources
using lossless compression; scene-specific names prevent cross-output overwrites.

Used TMX/TSX animations and multi-cell atlas tiles are explicitly unsupported.
Used TMX animations are detected before texture generation, so a rejected import
preserves the existing scene and assets instead of silently dropping animation.
Filesystem saving is not a fully atomic transaction: unexpected write failures
after generation starts remain an importer limitation.

Full-grid chunks written by the current import and obsolete compact chunks owned
by that output are removed only after successful scene saving. Arbitrary assets
and other visual outputs in the same directory are not deleted. Generated binary
resources now also reload correctly from `user://` test outputs.

## Regression prevention

The existing texture-storage CI check still rejects non-portable/non-lossless
resources. A new atlas-layout check also rejects unmarked new output, unused
sources/tiles, invalid cell alternatives, oversized canvases and incorrect padding.
It scans generated `*.tileset.tres` and validates their paired visual scenes.

The 35 existing visuals have explicit SHA-256 exceptions for BOTH their TileSet
and paired scene. These are immutable migration exceptions, not evidence that
all existing maps have been compacted. Any new or edited output must satisfy the
new contract. Do not refresh the baseline to work around a failed check.

Both new checks are registered in the project test list; the texture CI workflow
runs the importer, compactor, storage and layout checks. GitHub CI itself has not
been run here: this task does not authorize a push.

## Focused local evidence

- `tmx_visual_importer_check.gd`: compact output and existing layer/flip fixtures pass.
- `tmx_atlas_compactor_check.gd`: exact tile pixels, alternative transforms/data,
  custom data, physics polygons, source splitting, external saved references,
  repeated imports and same-directory outputs pass. Deliberate raw textures and
  missing definitions are rejected. The actual CI entry point accepts a new compact
  fixture and rejects its deliberately removed version marker.
- `generated_map_texture_storage_check.gd`: 331 existing textures pass.
- `generated_map_atlas_layout_check.gd`: 35 unchanged legacy exceptions pass;
  temporary new fixtures are cleaned up after their positive/negative checks.
- `pokeaether_tmx_importer_check.gd`: the shared parser/builder legacy fixture passes.
- `pallet_compact_atlas_check.gd`: the retained prototype passes.
- The same Pallet check with `--import-source` freshly imports the artist's real
  Pallet Town TMX into an isolated, automatically cleaned test directory. All
  4,376 cells and 325 unique tiles match the original decoded RGBA pixels,
  properties and door split pieces. Seven used sources total 1,843,200 base RGBA
  bytes (1.7578125 MiB). This is not a physical-RAM/GPU measurement or a new live
  battle benchmark; block 3 contains the accepted runtime evidence.

New script UID sidecars were generated by the slot editor. The actual UID check
is `tools/check_godot_uid_sidecars.sh`; it passes. An earlier attempted
`godot_uid_sidecar_check.gd` command found no such script and was not a passing
check.

## Remaining work

Migrate other existing visuals in bounded map groups with source/visual comparison
and focused runtime checks. The 35-entry baseline must shrink as migrations land.
Do not bulk regenerate maps without checking their artist source and gameplay
bindings. No complete development certification, promotion, push, export release
or production operation is part of this block.
